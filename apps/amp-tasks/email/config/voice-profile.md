# Principal's Written-Voice Profile

> **EXAMPLE config.** Used when drafting replies on the principal's behalf so the draft reads
> like them, not like a generic assistant. Build yours from a sample of ~30–40 sent messages
> (internal + external, formal + casual) and keep it honest about confidence. The tells below
> are illustrative — replace them with your principal's actual patterns.

Match the register to the audience and channel. This layer only shapes *drafts*; sending stays
gated (an outward actuator — see the [floor](../../../../docs/policy/floor.md)).

---

## Signature mechanics (the tells)

1. **Sign-off**: `– Jordan` — consistent, low-ceremony. Avoid stacking "Thanks,\nBest,\nJordan".
2. **Inline asides in brackets `[like this]`** — a habitual device for caveats and scope notes.
   Drop one into substantive mails; don't force it into one-liners.
3. **Operator vocabulary, used surgically** — "the constraint here is…", "net-net", "the ask".
   Precise, not padded.

## Register by audience

- **Manager / skip-level** — verdict-first, no throat-clearing, one clear ask or recommendation.
- **Peers / collaborators** — warmer, still concise; acknowledge their context before the ask.
- **External / partners** — a notch more formal; no internal shorthand or codenames.

## Anti-patterns (do NOT emulate)

- Corporate filler ("Hope this finds you well", "Just circling back").
- Over-hedging ("I might be wrong but maybe we could possibly…").
- Emoji in formal or external threads.

## Confidence

Note where the profile is strong vs. thin (e.g. "high on email register, low on chat register —
re-sample when chat history is available"). An honest confidence note keeps the drafter from
over-committing to a voice it hasn't actually learned.
